# Contributing to DELIGHT

Thank you for your interest in contributing to DELIGHT! This document provides guidelines for contributing to the project.

## Getting Started

1. Fork the repository
2. Clone your fork: `git clone https://github.com/YOUR_USERNAME/DELIGHT.git`
3. Create a new branch: `git checkout -b feature/your-feature-name`
4. Make your changes
5. Test your changes thoroughly
6. Commit your changes: `git commit -m "Add: description of your changes"`
7. Push to your fork: `git push origin feature/your-feature-name`
8. Open a Pull Request

## Code Style

- Follow PEP 8 style guidelines for Python code
- Use meaningful variable and function names
- Add docstrings to all functions and classes
- Keep functions focused and concise
- Add type hints where appropriate

## Commit Messages

Use clear and descriptive commit messages:
- `Add:` for new features
- `Fix:` for bug fixes
- `Refactor:` for code refactoring
- `Docs:` for documentation changes
- `Test:` for adding or updating tests

## Testing

Before submitting a PR:
- Ensure all existing tests pass
- Add tests for new functionality
- Test on both CPU and GPU if applicable
- Verify code compiles without errors

## Pull Request Process

1. Update the README.md with details of changes if needed
2. Ensure your code follows the project's code style
3. Make sure all tests pass
4. Update documentation as needed
5. Your PR will be reviewed by maintainers

## Reporting Issues

When reporting issues, please include:
- A clear description of the problem
- Steps to reproduce the issue
- Expected behavior vs actual behavior
- Environment details (OS, Python version, CUDA version, etc.)
- Error messages and stack traces if applicable

## Questions?

If you have questions, feel free to:
- Open an issue with the "question" label
- Reach out to the maintainers

Thank you for contributing!
